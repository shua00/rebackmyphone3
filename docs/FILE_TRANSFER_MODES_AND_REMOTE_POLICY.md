# 文件传输双模式与远程策略架构

状态：**已确认的项目级 P0 产品与架构契约；分阶段实施。**

适用范围：Android、Rescue2、Server2。文件传输与聊天、远程指令共享统一网络感知能力，但保持独立协议、队列、存储、授权和恢复边界。

## 1. 已确认的产品决策

1. 默认模式为**简易快捷模式（quick）**。
2. 用户可以在简易快捷模式与安全认证模式之间切换，除非有效远程策略限制或强制指定模式。
3. Rescue2 和 Server2 均可向设备下发模式切换或模式限制策略。
4. 远程管理可以：
   - 指定当前模式；
   - 强制仅允许简易快捷模式；
   - 强制仅允许安全认证模式；
   - 设置默认模式但保留用户切换权；
   - 解除限制并恢复用户自主选择。
5. 快捷模式下，接收方可选择逐次确认，也可选择自动接收。
6. 自动接收不是无条件接收：必须继续执行来源范围、存储配额、文件大小、速率/并发、完整性校验和拒绝策略。
7. 两种模式共用文件传输体验和可靠传输引擎，不维护两套互不兼容的数据面。

## 2. 模式与接收策略分离

### 2.1 Transfer mode

- `quick`：无需预先配对或用户手动身份认证，适用于受限范围内的快速发现和传输请求。
- `secure`：要求可信身份认证和授权，适用于远程、不可信网络及需要强身份保证的传输。

快捷模式的“免认证”特指不要求用户预先配对或手动执行身份认证流程，不代表允许静默写入文件或接受任意网络来源。至少要有传输请求与接收策略控制、基本会话完整性保护、资源限制和文件完整性校验。快捷模式不提供与安全认证模式等价的强身份保证。

默认不得把快捷模式开放成跨公网的匿名文件入口。跨网/中继传输必须使用安全认证模式及其授权会话；如果设备被强制 quick，跨网安全传输能力不可用，应明确报告策略限制，不能静默降级或绕过策略。

### 2.2 Receive policy

接收策略独立于模式保存：

- `ask_each_time`：每次请求都由接收方确认。
- `auto_trusted`：匹配本机可信来源规则的发送方自动接收，其他来源仍需确认或拒绝。
- `auto_all_allowed`：在设备当前明确允许的来源、网络和资源范围内自动接收。

默认快捷模式不强制开启自动接收；首次默认接收策略为 `ask_each_time`。用户可自行改为自动接收，远程策略可限制允许的自动接收级别。自动接收永远不得绕过存储配额、大小/类型限制、限速、并发上限、完整性校验或系统安全防护。接收文件不得自动执行或安装。

## 3. 远程策略模型

建议使用独立、可版本化的 `TransferPolicy`：

| 字段 | 含义 |
|---|---|
| `transfer_mode` | `quick` 或 `secure` |
| `mode_control` | `user_selectable`、`force_quick`、`force_secure` |
| `default_mode` | 用户自主选择时的默认模式 |
| `receive_policy` | `ask_each_time`、`auto_trusted`、`auto_all_allowed` |
| `max_receive_policy` | 管理端允许的最高自动接收级别 |
| `policy_owner` | 管理策略来源/授权主体 |
| `policy_revision` | 单调递增的策略修订号 |
| `policy_id` | 唯一策略标识 |
| `issued_at / expires_at` | 策略签发和有效期 |
| `effective_status` | pending、applied、rejected、expired、failed |
| `last_error` | 应用失败原因（如有） |

策略指令必须经过现有设备管理身份与权限校验，绑定目标设备、策略 ID、修订号和有效期；重复指令幂等处理，过期或低版本策略不得覆盖新策略。设备回报“已接收”与“已生效”必须区分。

### 3.1 策略语义

- `user_selectable`：设备用户可以在允许的模式范围内切换；本地默认值为 quick。
- `force_quick`：设备只能使用 quick。
- `force_secure`：设备只能使用 secure。
- `default_quick` / `default_secure`：设置用户自主模式下的默认值，不剥夺用户切换权。
- `release_control`：解除远程模式限制，恢复用户自主选择；不得擅自重置用户的接收偏好。

有效强制策略优先于用户本地选择；用户选择优先于系统默认值。管理端限制接收策略时，设备只能选择不高于管理端允许上限的接收策略。

### 3.2 Rescue2 与 Server2 的策略冲突

Rescue2、Server2 均可成为策略下发端，但不能采用“谁最后发包谁覆盖”或设备端不确定的竞态规则。

策略必须有可验证的管理主体、授权范围和单调修订号。若两个管理端共享同一设备管理权威/策略协调器，则由该权威签发统一 revision，设备只应用更高且有效的 revision。若两端属于不同管理域，则必须先配置明确的设备策略权威或授权优先级；未配置时，对冲突的强制策略拒绝覆盖并上报冲突，不自行猜测 Rescue2 或 Server2 谁优先。此管理权威配置是实现前置条件。

## 4. 离线、策略更新与进行中传输

- 设备离线时保留最后一次成功应用的有效策略；不得因短暂断网自动降级为 quick。
- 有明确 expires_at 的策略到期后，按已定义的管理域失联策略处理；不得把“无法联系管理端”解释为自动放宽权限。默认保留最后已知强制限制，直到收到有效解除/更新策略。
- 收到策略后先验证签名/授权、目标设备、revision、有效期和字段组合，再原子应用并持久化。
- 策略应用失败时保留最后一个有效策略，向管理端报告失败；不能只回报指令已接收。
- 从 quick 强制切换到 secure：立即禁止新的 quick Offer；已有 quick 传输不得继续建立新的未授权会话。对已接受的传输按安全边界中止并保留可恢复元数据，恢复后必须在 secure 下重新协商和授权，不得把 quick 会话直接升级为 secure 会话。
- 从 secure 切换到 quick：停止创建新的 secure-only 传输；已建立的 secure 传输可按会话策略完成或安全终止，但不得因切换而降低现有会话的安全性。
- 解除强制策略后恢复用户自主选择，并保留用户此前接收策略；若该接收策略高于当前管理端允许上限，则保持受限状态并提示用户。

## 5. 用户体验

目标流程：打开文件传输页自动发现候选设备 → 选择设备和文件 → 发送 Offer → 接收端按当前模式及接收策略确认/自动接收 → 显示进度、速度和结果。

用户界面必须清楚显示：
- 当前模式（快捷/安全认证）；
- 当前是否被 Rescue2 或 Server2 管理/强制限制；
- 用户能否切换；
- 当前接收策略；
- 自动接收的来源范围与限制；
- 远程策略最后更新时间及应用状态。

正常发送不应要求用户填写 Peer ID、IP、端口或手工配置底层通道。协议中的 Offer/Accept/Reject/Chunk/ACK/校验/恢复保留在底层，不要求用户理解。

## 6. 统一网络感知的消费契约

文件传输模块按需消费统一网络感知提供的候选设备、可信路径、路径租约、连接状态和路径质量事实；不能自行重复建设一套全局网络扫描与设备在线判断。

路径选择必须同时满足网络可达性和 TransferPolicy：
- quick 仅使用当前策略允许的快速发现/本地路径范围；
- secure 可使用经过认证的 LAN 路径或已认证的出站会话/受控中继；
- 跨 NAT 不依赖 UDP 广播穿透；
- 无可用且被策略允许的路径时，明确报告不可达/策略禁止，不得降级绕过。

网络感知只提供路径事实和选择能力，不拥有文件接收授权。TransferPolicy 决定允许的模式与接收权限，文件传输引擎负责 Offer、数据传输和可靠性。

## 7. 共用传输引擎与安全底线

两种模式共用独立文件传输数据面和生命周期：

- Offer / Accept / Reject / Cancel；
- 分块传输、逐块 ACK、有界重试；
- SHA-256 完整性校验；
- 断点续传、进程重启恢复；
- 传输账本、过期处理和资源配额；
- 进度、速度、失败原因与最终结果。

聊天协议、聊天 Outbox/Inbox、远程指令执行账本、文件传输队列和文件存储必须保持隔离。快捷模式不复用聊天配对凭据作为隐式授权；安全模式也不把配对状态等同于文件接收许可。

## 8. 实施顺序与验收

当前不以新增模式代码打断 LAN P2P v2 基础回归。建议依赖顺序：

1. 收口普通 LAN 双 Android 对讲回归及 peer.hello/peer.ack/RouteBinding/消息 ACK。
2. 收口 STA/AP 多 Listener 的 ingress、ACK、generation 和有限回退。
3. 统一文件传输 Offer/接收策略/传输账本与现有分块、校验、恢复能力。
4. 实现 quick/secure 两种模式及本地设置。
5. 实现 Rescue2/Server2 远程策略签发、版本、权限、回执和冲突处理。
6. 实现跨网络安全会话下的 Android ↔ Rescue2 双向文件传输。

必须覆盖的自动化与真机验收：
- 新设备默认 quick，用户可以切换；无远程限制时本地选择持久化。
- quick 的 ask_each_time、auto_trusted、auto_all_allowed 三种接收策略及来源/资源限制。
- secure 必须完成身份认证和授权；未认证/过期会话不能传输。
- Rescue2、Server2 分别切换模式、强制 quick、强制 secure、解除限制。
- 双管理端 revision 冲突、重复指令、过期指令、低 revision、离线恢复和策略应用失败。
- 强制策略切换期间的进行中传输不得绕过新策略或降级安全性。
- 普通 LAN 快速发现和发送不能引入不必要的周期扫描、额外线程或多路径 fan-out。
- 两种模式均验证文件摘要、分块 ACK、失败重试、断点续传和进程重启恢复。

CI、组件测试和真机验收分开记录；文档完成不代表生产代码或真机能力完成。
