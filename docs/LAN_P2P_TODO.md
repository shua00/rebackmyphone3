# LAN P2P 后续 TODO 与验收门槛

更新：2026-11-25

本文记录当前安全配对闭环和后续管理能力，不代表尚未实施的能力已经可用。

## 当前优先级：文件传输安全配对闭环

- [ ] 建立独立配对控制传输：与聊天 UDP/ACK/Outbox 隔离，也与文件数据 TCP framing 隔离。
- [ ] 配对请求/响应携带协议版本、双方 Peer ID、临时 P-256 公钥和随机 nonce；transcript 必须绑定双方身份与全部交换材料。
- [ ] 双端显示一致的 6 位 SAS；本地用户确认和远端经密钥认证的确认都完成后，才允许提交 per-peer secret。
- [ ] 任一端拒绝、SAS 不匹配、超时、取消、断线、重放或确认认证失败，都不得写入凭据。
- [ ] 配对成功后读取现有 peer-secret map 并合并新 peer，不能覆盖其他设备；旧 v1 shared-secret 数据只按原 allowlist 兼容读取，不得让新设备悄悄共用全局 PSK。
- [ ] 替换手动输入 global shared secret / Peer ID 的配对 UI；提供明确的请求方身份、SAS、确认/拒绝和失败状态。
- [ ] 独立发现和 endpoint cache 是必要兜底；聊天 UDP 在线设备列表只能作为可选提示，不得成为配对凭据或必要依赖。
- [ ] 验证错误 SAS、单边确认、远端拒绝、确认伪造、重放、超时、断线、重复请求、peer 隔离、legacy read 和 no-fallback。
- [ ] 双机真机验收：Android 6+ 兼容性、不同 ROM、网络切换、发现兜底、配对失败不落盘、成功后 per-peer 文件传输。

## 后续架构 TODO：rescue2 超级管理权限（已纳入规划，暂不阻断当前配对）

- [ ] rescue2 独立管理员身份与长期签名密钥；不得复用普通设备 peer secret 或建立全设备共享万能密钥。
- [ ] 通信策略管理层（建议 CommunicationPolicyManager）与聊天/文件传输执行层解耦；策略版本化、签名验证、作用域限制、有效期、撤销和审计。
- [ ] 普通设备、受管理设备、rescue2 管理端分级授权；rescue2 可配置对讲和文件传输策略，但不得绕过 Android OS sandbox 或对端接收授权。
- [ ] 支持 rescue2 发起临时免长期配对的文件发送任务：使用短期 capability token，绑定管理员身份、任务 ID、目标范围、文件摘要/大小、操作范围、过期时间和一次性 nonce，并防重放。
- [ ] 访客接收必须由接收端主动开启限时接收窗口或对具体任务明确授权；未认证模式须隔离接收目录并由用户确认保存/打开，明确提示无身份认证时不能保证抗中间人攻击。
- [ ] 不支持“对任意未安装兼容接收端的 Android 手机强制送达”；必须存在兼容接收组件/服务或用户主动使用系统分享入口。
- [ ] rescue2 管理能力不得依赖 server2/chat.py 在线；不得改变聊天与文件传输的协议、状态、存储隔离，也不得削弱普通设备默认安全策略。

## 后续阶段

- [ ] 完成配对闭环后，再集中接入 rescue2 管理策略与临时授权通道。
- [ ] 公共模块重构延后至双机真机验收完成之后。
- [ ] 文件传输 UI 继续遵循统一聊天入口 + 独立文件管理页；功能默认关闭，通过设置开启。
