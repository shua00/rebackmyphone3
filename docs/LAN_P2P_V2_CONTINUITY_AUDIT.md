## 3. 必须修正项

### P0：恢复 Rescue2 原有日志拉取并隔离诊断功能

文件：`tests/test_rescue2_legacy_log_pull_diagnostics.py`

旧版 `pull_logs_multi()` 应与基线 `481dc2c` 的函数实现保持一致，不调用 `_diag_event()` 或 `_diag_exception()`。新增诊断采集必须另设入口、任务状态和传输协议，支持单设备与批量两种目标模式。当前修正测试采用 AST 精确提取函数体，并断言旧路径不依赖诊断记录器。

此前测试函数体截取错误的历史问题：

```python
body = body.split("\\n# ===== ADB 核心模块", 1)[0]
```

它匹配的是字面反斜杠加 n，而不是换行符。应改为：

```python
body = body.split("\n# ===== ADB 核心模块", 1)[0]
```

修复后增加测试，确认截取结果不包含后续函数/模块内容；最好对 `pull_logs_multi` 做可控依赖的行为测试，验证拒绝广播目标、逐目标派发、完整/部分/超时结果及诊断事件字段。不要只依赖源码字符串断言。

### P0：补齐长消息广播协议测试闭环

重点文件：
- `app/src/main/java/com/example/devicefinder/TrackingService.java`
- `app/src/main/java/com/example/devicefinder/LanChatStore.java`
- `tests/test_lan_p2p_core.py`

必须覆盖：
- 同一广播 messageId 的多个 peer 分别维护独立 ACK 位图；
- ACK 乱序、重复、迟到、未知 peer，以及已有 verified route 与首次 ACK 的竞态；
- 单一 peer 丢片时只对该 peer、该窗口重传，不推进其他 peer；
- 首轮广播窗口 ACK 部分缺失、后续窗口部分缺失；
- 发送中 ACK 与窗口推进竞态；
- 进程重启后从 SQLite 恢复每个 peer 的独立位图和目标端点；
- 分片 ACK 不能被提升为最终送达；只有完整消息持久化 Inbox 后的 `chat.ack` 才算最终送达；
- 临时目标数量上限、过期清理和不写入可信设备目录。

这些测试完成前，广播长消息只能标记为“代码已实现、协议测试未闭环”，不能标记为验收完成。

### P1：发现刷新测试补充边界

现有 `LanTransferDiscoveryTest` 验证节流槽位和并发 CAS 行为，方向合理。后续确认：
- 用户点击刷新时服务未运行/正在启动/正在关闭的行为；
- 节流命中时 UI 状态不会错误显示已经广播成功；
- UDP 发送失败后是否允许合理重试；
- 网络切换期间旧 Network/socket 不会继续发送；
- 双机真机确实收到对端发现广播。

### P1：长文本输入做 UI 行为验收

现有测试确认多行属性和 Ctrl+Enter 判断，但尚未验证不同 Android IME 对 `IME_ACTION_SEND` 与多行输入的实际行为。真机验证物理 Enter 换行、IME 发送、Ctrl+Enter 发送、发送后焦点/键盘状态，以及输入框显示行数限制不截断消息内容。
