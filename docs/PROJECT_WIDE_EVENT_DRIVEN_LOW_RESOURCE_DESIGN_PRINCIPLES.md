## 1. 总目标

项目追求：

> **低资源常驻、事件驱动感知、按需建立连接、已验证路径快速通信、可靠投递与自动恢复。无业务或无变化时近零主动消耗；有业务或环境变化时快速响应。**

“近零资源”不是承诺设备完全不运行代码或后台网络永远零功耗，而是要求：
- 没有有意义的事件时，不做无效扫描、轮询、空转、重复握手、无效发包或无界任务；
- 必要的接收能力采用阻塞等待、系统事件或平台提供的低开销机制；
- 只有受影响的设备、路径、消息或任务被唤醒；
- 资源消耗随实际活动和有效路径规模增长，而不是随设备总数、编译进来的适配器种类或历史记录无限增长。

Android 的 Doze、省电策略、后台执行限制、Wi-Fi 芯片/驱动和网络环境会影响后台唤醒与时延。因此“即时”是工程目标和实测指标，不是对所有休眠状态、OEM 和网络拓扑的绝对保证。

## 2. 即时性与低消耗的统一模型

将工作划分为四层：

1. **感知常备**：维护系统已提供的网络/设备/任务状态；使用网络回调、进程内事件和阻塞式接收，不靠高频主动轮询。
2. **事件触发**：网络/接口变化、设备主动广播、已验证路径失效或恢复、用户操作、任务状态变化时，产生有作用域的事件。
3. **按需验证与决策**：只验证受影响的 peer × path；验证通过后更新对应路由租约和状态。
4. **按需传输与恢复**：使用已验证路径快速发送；失败时对具体目标进行有限恢复；无有效路径时保留任务并等待真实事件。

即时性主要来自常备接收能力、及时事件分发和已验证路径复用；低消耗主要来自消除无意义轮询、全量扫描、重复探测、广播风暴和无界重试。

## 3. 项目通用原则

### P1. 事件驱动优先，轮询必须证明必要性

- 优先使用操作系统回调、阻塞式 I/O、已有连接/Listener 事件、业务状态变化事件。
- 周期任务只有在平台没有可靠事件来源、且业务确有期限/租约需求时才允许存在。
- 每个周期任务必须说明目的、对象范围、频率/退避、终止条件、功耗预算和可观测指标。
- 不允许用定时扫描弥补事件订阅、状态机或唤醒链路设计错误。
- 无伙伴、无网络、无待处理动作时，不应持续唤醒业务线程或制造网络流量。

### P2. 感知、身份、可达性和授权必须分离

不得混淆：
- 看见网络/接口 ≠ 目标设备存在；
- 发现设备/收到广播 ≠ 身份可信；
- 身份可信 ≠ 当前网络路径可达；
- socket 绑定成功 ≠ 端到端可达；
- 收到普通 ACK ≠ 消息已持久化；
- 消息已持久化 ≠ 用户已读；
- HTTP accepted / UDP send 成功 ≠ 业务操作已执行。

每个状态必须有明确证据、来源、有效期和状态转换条件。涉及发送授权时采用 fail-closed 原则。

### P3. 事件必须携带作用域，唤醒只影响相关对象

事件至少应明确其作用域，例如：
- 全局网络/服务生命周期；
- 某个网络路径；
- 某个 peer；
- 某条 message_id × peer_id 投递目标；
- 某个 transfer_id；
- 某个 commandId / operationId。

peer 级恢复不能误重开所有 peer；路径变化不能无差别重置所有消息预算；单个文件任务的取消/过期不能影响聊天消息或其他文件任务。事件在队列繁忙、暂时无路由或存储暂时失败时不得静默丢失；需要持久化或合并时，必须保留原始作用域和幂等语义。

### P4. 状态单一所有权、持久化事实与运行时缓存分工明确

- 每类业务状态指定唯一权威 Store / Repository / 状态机。
- 内存缓存用于加速，不得凌驾于持久化账本或认证事实。
- 进程重启后必须能从持久化状态恢复应恢复的任务；临时 socket、线程、nonce 和 lease 不得伪装成跨进程有效。
- 数据库迁移必须增量、可验证，不得无故清空用户数据。
- 状态转换应幂等、可重入，并明确终态、过期、取消和人工重试语义。

### P5. 任务和资源必须有界

- 线程/worker 数、队列容量、并发数、批次大小、候选路径数、缓存大小、消息/文件大小和保留期限均须有硬上限。
- 队列满时采用明确背压/拒绝/持久化恢复策略，不允许无限堆积。
- 禁止 thread-per-packet、无界 fan-out、无限递归重试和无上限历史状态。
- 批处理必须保证剩余工作有可靠后续唤醒，不能靠无延迟递归清空积压。
- 资源所有权必须明确；路径/服务/任务结束时及时关闭 socket、取消任务、释放文件句柄和清理临时数据。

### P6. 快路径优先，复杂能力按需激活

- 稳定的普通单路径场景必须保持 O(1) 或等价常数级快路径。
- 多路径枚举、质量评估、额外 Listener、备用路由和诊断采样只在确有多路径或异常需求时激活。
- 不得因支持未来适配器而给当前普通 LAN 场景增加常驻线程、周期扫描或每包额外分配。
- 质量评分必须来自真实 RTT、ACK、失败和重试样本；样本不足时使用明确的保守策略，不编造质量值。

### P7. 通信控制面与数据面分离

- 发现、身份验证、能力协商、路由租约和任务控制属于控制面。
- 消息正文、分片和文件字节属于数据面。
- 短消息、长消息、文件传输、实时指令可共享身份和网络感知事实，但应保持适合各自语义的独立传输、账本和状态机。
- 大数据传输不得阻塞短消息 ACK/控制通道；控制队列不得被大块数据占满。

### P8. 可靠性必须由端到端状态证明

- 发送尝试、socket send 成功、对端收到、对端持久化、业务执行成功是不同阶段。
- 使用稳定 ID、幂等处理、去重、ACK 关联校验、有限重试和可恢复账本。
- 只有符合身份、目标、消息/任务 ID、路径/端点和状态约束的确认才能推进状态。
- 部分成功必须按目标分别记录；一个目标完成不能替代其他目标。
- 对有时效性的指令必须有 deadline/TTL，过期后不能因网络恢复而盲目执行。

### P9. 失败恢复必须有界且由真实原因触发

- 网络变化、Listener 重建、伙伴重新出现、路径重新验证、明确的发送失败等可触发对应范围恢复。
- 无真实发送尝试、无可用路径、无伙伴时，保留待处理账本并等待事件，不以 Outbox 自我轮询制造发现活动。
- 退避用于处理真实失败和资源冲突，不替代正确事件感知。
- 恢复任务应合并重复事件、保留作用域、限制并发，并在完成/失效/过期后终止。
- 任何“立即重试”分支都必须证明它来自真实外部恢复事件，而不是内部调度标记。

### P10. 安全、隐私与可审计性是基础约束

- 设备身份、配对信任、认证、授权和机密性分别定义；共享密钥/HMAC 不得被描述成唯一设备身份或端到端加密。
- 远程控制必须鉴权、授权、幂等、可追踪，并区分接收、接受、执行和完成。
- 日志记录状态、ID、耗时、错误码和决策原因；不得记录密钥、令牌、聊天正文、文件内容或不必要的个人信息。
- 设备管理中的“删除服务端记录”不得默认等同于远程擦除或停止设备。
- 高风险操作需明确权限、确认、审计和可恢复边界。

### P11. 可观测性应解释决策，而不是制造噪声

关键事件日志应回答：
- 谁触发了工作？事件来源和作用域是什么？
- 选择了哪条路径？为什么？
- 是否真正发出数据？还是仅排队/等待验证？
- 状态是否持久化？ACK 是否通过验证？
- 为什么重试、跳过、暂停或终止？
- 消耗了多少时间、流量、CPU/唤醒和队列容量？

重复高频日志应合并、采样或按状态转移记录；不能通过降低日志级别掩盖真实循环。日志应可关联但不暴露敏感内容。

### P12. 分层实施、兼容优先、实测验收

- 先定义边界和状态机，再实现适配器与 UI；避免大规模重写替代针对性修复。
- 保留已验证的生产路径和兼容性；协议升级必须有版本/能力协商与迁移策略。
- CI 验证代码和确定性测试；真实设备验收验证 Android 生命周期、Wi-Fi 行为、路由器/AP 隔离、休眠、进程重启和真实时延。
- 性能结论必须来自代表性设备和拓扑测量，不设没有测量依据的统一 CPU/耗电/时延承诺。
- 每次改造都要有回归基线、故障注入、日志证据和明确完成标准。

## 4. 即时 LAN 通信专用原则

1. Listener 采用阻塞接收；网络变化时由系统回调驱动重建，不用短超时轮询。
2. Listener 启动/新路径启用时可进行一次有界发现通告；收到伙伴主动 HELLO 后执行身份/nonce/端点/路径验证。
3. 候选端点仅是发现线索；只有当前 path + socket/listener generation 上验证成功的 route 才可发送。
4. 已验证 route 在有效租约内直接复用；不因每条消息重新发现或握手。
5. 普通聊天消息单播到固定收件人快照；不默认广播正文，不默认多路径重复发送。
6. 只有真实路径恢复事件才精准唤醒对应 peer 的 Outbox 目标；无伙伴时安静等待。
7. 历史 IP 不能无限期反复 challenge；候选必须有来源、有效期、冷却和淘汰策略。
8. Outbox 是可靠投递账本，不是网络探测器；没有可验证路径且没有真实发送尝试时，不应周期性扫描/重试。
9. 单路径普通 LAN 快路径不得因为多路径支持而增加额外常驻工作。
10. 发现、路径验证、聊天消息 ACK、长消息分片 ACK 和文件传输确认使用不同语义，不互相冒充。

## 5. 关于恶意软件通信技术的研究边界

恶意软件可能使用长连接、反向连接、事件触发、低频心跳、任务队列、断线恢复和多通道回退等通用网络工程模式。可以从防御和系统设计角度研究其资源特征、故障模式和检测方法，并评估这些通用模式是否适合合法设备通信。

本项目不采用或实现恶意用途机制，包括隐蔽控制通道、流量伪装以规避检测、持久化植入、隐藏进程/服务、规避安全软件、未经授权的远程控制或数据窃取。合法通信应保持用户可控、可审计、可撤销和权限明确。

## 6. 外部项目参考与取舍

这些项目仅用于提炼机制，不照搬整体架构或引入不必要依赖：

- [NectarLink](https://github.com/thtbee/nectarlink)：协议版本/能力协商、身份与配对信任、控制面与数据面分离、连接抽象、完整性校验和续传。
- [Knit](https://github.com/getknit/knit)：传输抽象、消息 ID 去重、TTL、存储转发、消息生命周期、资源预算。当前单跳 LAN 不引入 BLE/Wi-Fi Aware Mesh、泛洪或周期 digest。
- [飞秋安卓版](https://github.com/zyqg/feiq-android)：LAN 发现、网络回调后重建 socket、职责分层、UDP 消息与 TCP 文件分工；不照搬以 IP 为身份或缺少持久化可靠账本的部分。
- [KouChat](https://github.com/blurpy/kouchat)：无中心 LAN 发现和点对点交互体验；发现/发送成功不等于可靠送达。
- [LanChat](https://github.com/zyqg/LanChat)：简洁 LAN 自动发现和点对点机制参考。
- Simple LAN Chat：仅作为此前讨论过的 UDP 广播/心跳/分片思路参考名称；当前未在本项目文档中确认其准确仓库地址，因此不附猜测链接，也不据名称推断能力。
- [IP Messenger 官方协议与源码](https://github.com/shirouzu/ipmsg)：成员发现/应答、接收确认与阅读确认分离、UDP 消息和 TCP 文件通道、有界重试。
- Geogram、Jami、qaul：去中心化和跨网络通信的比较研究对象；Mesh、多跳、relay、BLE/Wi-Fi Aware 等能力不自动进入当前 LAN 范围。

明确取舍：
- 当前优先做好 IPv4 LAN 单跳、Android/PC 互通、身份/路径验证、可靠投递、网络变化恢复和低资源快路径。
- 不因研究项目的技术先进而提前引入 QUIC/TLS 全面替换、Mesh、多跳泛洪、BLE/Wi-Fi Aware 或跨互联网 relay。
- 先完成现有架构的证据审计与真机验收，再依据明确需求扩展传输适配器。

## 8. 与当前审计的关系

本文件先确立设计目标和全局原则，不代表当前代码已全部符合。当前 LAN P2P 只读审计继续优先检查：
1. Outbox 无伙伴时的周期唤醒；
2. 历史 IP 定向 challenge 与广播发现的触发源、冷却和淘汰；
3. 网络/伙伴/路径恢复事件的作用域与可靠唤醒；
4. Listener、socket、generation 和路径租约生命周期；
5. 单路径快路径及真实设备空闲资源表现。

任何修复必须遵守本文件与关联架构决策，不得通过降低日志级别、简单延长轮询间隔或增加常驻线程掩盖根因。
